# Rolling image context window

Master Goal now defaults to sending only the newest raw image with each model request. Screenshot-heavy sessions can retain their history without sending every previous screenshot back to the model.

- Set native plugin `options.imageWindow` to 1 (default), 2, 4, or any non-negative safe integer. Zero excludes all raw images.
- Enforced before provider serialization for normal, autonomous, compaction, title and session-generation requests, including sessions without an active goal.
- Handles user attachments and tool/MCP screenshot files. Preserves text, non-image files, tool-call/result pairs and persistent screenshots.
- Native plugin options override `MASTERGOAL_IMAGE_WINDOW`; invalid selected settings reject startup. Installer upgrades preserve options.
- Sidebar/status displays the limit; pruning diagnostics contain counts only.
- OpenCode plugin dependency remains pinned to 2.0.22. Goal completion, forever mode and failure handling are unchanged.

## Update

Close OpenCode, then run:

```powershell
opencode service stop
npx --yes --package=github:darkmatter2222/opencode_mastergoal#v0.4.0 mastergoal install --global
opencode
```

Use `--local` instead of `--global` for a project installation. Existing installations need no new setting to get the default limit of one.

To configure the window, change your existing Master Goal registration in `opencode.json[c]` from its package string to an object, retaining that exact package path:

```json
{
  "package": "file:///YOUR-EXISTING-PATH/.mastergoal-runtime/node_modules/@darkmatter2222/opencode-mastergoal",
  "options": { "imageWindow": 2 }
}
```

Restart OpenCode after changing the setting. This does not change your inference server's own image limit.

## Validation and scope

Local verification passed 117 tests and 20 deterministic scenarios; packaged local/global install and uninstall passed. Actual OpenCode 2.0.22 captured three provider requests with image counts `[1,1,1]` from 100 stored image-bearing prompts. Configured limits 4 and 0 produced `[4,4,4]` and `[0,0,0]`. All 100 attachments remained in session export, and the default retained PNG was verified as the newest. Unit endurance coverage includes 1,000 growing turns.

Release publication requires successful cross-platform CI on the exact release commit. The provider canary uses a local OpenAI-compatible fake, not a live vLLM model. Other plugins must not insert images after this filter. Opaque provider-side history and model calls outside OpenCode session hooks are outside its scope.

The attached tarball contains the compiled runtime, with SHA256SUMS. This is a GitHub release; the package is not published to the npm registry.
